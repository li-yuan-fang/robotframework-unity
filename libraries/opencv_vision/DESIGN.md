# OpenCVVision 库设计约束

状态：首版已按本文档实现，离线验收通过；实机验证待在目标设备上进行。使用方式与已验证依赖版本见同目录 `README.md`。

## 1. 目的与目录边界

解决同一按钮在截图中的尺寸与模板素材尺寸不同而无法匹配的问题，并为误匹配提供可复现的本地诊断材料。

- 库目录固定为 `libraries/opencv_vision/`，Robot Framework 库名为 `OpenCVVision`。
- 未来的入口、实现模块、依赖声明、说明、样例和测试均放在该子目录中，不直接在 `libraries/` 根目录添加库文件。
- 图像匹配完全在本机完成；除复用已配置的 Appium 会话获取截图外，不访问外部服务，不上传截图至模型服务，不依赖 Appium 的 images 插件。
- 实现、文档及新增验收测试限于该库子目录；依赖在本地隔离环境验证，不修改现有业务资源和测试，不执行 GitHub 同步、commit 或 push。

## 2. 首版范围

主要使用方式为：调用者指定模板，库从现有 Appium 会话获取内存截图，完成匹配后返回 `ImageElement`。

截图的获取、传递和解码全部在内存中完成。本库不得通过临时图片、截图路径或先保存后读取的方式连接这些步骤。Python 层另外提供内存图片入口，便于无设备测试与复现。

必须支持：

1. 等比例多尺度模板匹配。
2. 可选搜索区域 ROI。
3. 成功时返回包含位置、尺寸、中心点、分数及缩放比例的 `ImageElement`。
4. 区分未找到、候选存在歧义和输入/设备错误。
5. 默认不保存截图；显式启用诊断时，可将同一帧的内存数据导出为原始图像、标注图和参数记录。
6. 无设备、无 Appium 服务时，仍可将图片字节直接传入 Python 入口进行扫描与复现。

首版不实现：自动点击、内部等待重试、OCR、目标检测模型、旋转匹配、透视匹配、横纵方向分别拉伸、多目标批量返回、视频持续检测。等待和点击继续由现有 Robot 测试组织。

## 3. 对外接口

| 接口 | 必填输入 | 行为 |
| --- | --- | --- |
| Robot 关键字 `CV Find Image Element` | `template` | 从已连接的 AppiumLibrary 获取一次内存截图，匹配成功后返回 `ImageElement` |
| Python 接口 `find_image_in_memory` | `source_bytes`、`template_bytes` | 直接解码内存中的图片字节，匹配成功后返回同类型的 `ImageElement` |

`template` 接受模板文件路径或编码后的 PNG/JPEG `bytes`。路径仅用于读取模板素材；调用者不需要提供截图路径，也不需要自行获取 Appium driver。Python 内存入口仅接受图片字节，不接受截图路径，不隐式读取文件。

Python 匹配核心必须可独立调用，不依赖 Robot 全局状态或 Appium 会话。Robot 层只负责参数转换、日志、可选诊断输出和 Appium 适配。原计划中的 `Scan Image` 与 `Scan Screen For Image` 不再作为首版公开关键字。

两个入口均在唯一有效匹配时返回元素；未找到时抛出 `IMAGE_NOT_FOUND`，不同位置的候选存在歧义时抛出 `AMBIGUOUS_IMAGE_MATCH`。不能用空元素或错误位置满足成功返回。

`ImageElement` 是本次截图的定位快照，不是 Appium 服务端 WebElement；首版提供坐标与匹配信息，不隐式执行点击。原先的 OCR 关键字保持现有行为。

所有参数使用明确命名。数字字符串只在入口转换一次；布尔值不得被当作数值接受；NaN、无穷大及非法范围立即报错。

### 3.1 匹配参数

| 参数 | 默认值 | 约束 |
| --- | --- | --- |
| `threshold` | `0.80` | 接受匹配的最低分数，取值 `(0, 1]`；是算法分数，不是正确概率 |
| `scale_min` | `0.50` | 模板缩放下界，必须大于 0 |
| `scale_max` | `2.00` | 缩放上界，必须大于等于下界 |
| `scale_step` | `0.05` | 缩放步长，必须大于 0 |
| `roi` | 整张图 | 原始截图坐标中的 `(x, y, width, height)` |
| `score_margin` | `0.05` | 第一、第二个不同位置的候选需要满足的最小分差，取值 `[0, 1]`；设为 0 关闭歧义保护 |
| `debug` | `none` | `none`、`on_failure` 或 `always`；后两种为调用者显式请求导出诊断 |
| `debug_dir` | 启用诊断时取 Robot 输出目录下的 `opencv_vision` | 诊断输出的父目录；关闭诊断时不创建或访问该目录 |

Appium 入口额外接受 `appium_library=AppiumLibrary`，以支持库别名；以及 `coordinate_mode=screenshot`，默认仅返回截图坐标。调用者已确认截图覆盖完整窗口时，可以显式指定 `coordinate_mode=full_window` 请求窗口坐标换算，不从宽高比自行推断覆盖关系。

Python 核心的诊断默认关闭；调用者启用时必须提供输出目录，不能依赖 Robot 的 `${OUTPUT DIR}`。

以上为初始默认值，不承诺适用于所有素材。阈值和比例范围必须允许调用时覆盖，不提供自动降阈值策略。

## 4. 图像输入

- 设备截图使用 Appium Python 客户端的公开接口 `get_screenshot_as_png()`，得到 PNG `bytes`。
- 截图字节通过 `numpy.frombuffer` 与 `cv2.imdecode` 转成图像数组，直接传给多尺度匹配核心。禁止使用 `save_screenshot`、`Capture Page Screenshot` 或临时图片文件作为传递步骤。
- 内存入口支持编码后的 8 位 PNG 和 JPEG 字节，必须验证能被正确解码；首版不扩展为 Base64、路径或任意 ndarray 混合输入。
- 模板若传入文件路径，允许中文和空格；相对路径以当前进程工作目录解析，记录解析后的绝对路径。Robot 资源推荐通过 `${CURDIR}` 传入明确路径。
- 截图只采集一次，模板字节只读取一次；后续匹配和可选诊断复用本次内容，不重新取图，不因模板文件被覆盖而改变输入。
- 保留输入原始字节和原始颜色用于诊断；匹配时统一转换为 8 位灰度。
- 首版模板必须不透明；存在非 255 的 alpha 值时明确报错，不能静默忽略透明通道。推荐从设备截图中裁剪模板。
- 空图、解码失败及灰度标准差小于 1 的模板明确报错，避免归一化相关匹配在纯色模板上的退化。
- 使用解码后的像素方向和尺寸，不自动依据 EXIF 改变方向，不对原图做隐式旋转、镜像或裁边。

## 5. 多尺度匹配规则

1. 算法固定为 OpenCV `matchTemplate` 的 `TM_CCOEFF_NORMED`，首版不提供算法切换。
2. 每次扫描只使用同一帧原图；所有比例均与这一帧比较。
3. 模板按 `scale_min + k × scale_step` 生成比例，包含下界；若上界未落在步长序列中，额外包含上界。下界等于上界时只测试一个比例。
4. 浮点边界使用稳定计算，默认参数必须生成 31 个比例；参数展开超过 101 个比例时报参数错误，不能静默截断。
5. 宽高按比例四舍五入为整数，缩放后的相同宽高只计算一次；缩小时采用面积插值，放大时采用三次插值。
6. 缩放后任一边不足 3 像素、模板大于 ROI、或模板灰度方差退化时跳过该尺寸，并记录原因。所有尺寸都无效时报告 `NO_VALID_SCALE`，不作为未找到处理。
7. 从各比例的响应图提取空间局部峰值，丢弃 NaN 和无穷大分数；必须能保留不同位置的候选，不能每个比例只保留一个全图最大值，否则无法发现重复按钮。
8. 对同一位置的相近比例候选做非极大值抑制，首版以交并比 IoU 大于等于 0.30 作为重复候选判断，保留最高分。这个规则是几何启发式，不保证区分相互遮挡的目标。
9. 在合并后的候选中选取最高分。低于 `threshold` 时内部状态为 `not_found`；不同位置的第二候选也达到阈值，且分差小于 `score_margin` 时内部状态为 `ambiguous`；其他情况为 `matched`。公开接口仅在 `matched` 时构造元素，其余状态转换为相应异常。
10. 分数相同时按距原始比例 1.0 更近、再按坐标从上到下从左到右排序，以保证相同输入的结果稳定。歧义判断优先于排序，不靠排序消除歧义。

候选分数不是概率。扩大缩放范围、降低阈值和扩大搜索区域都可能增加误匹配。首版不承诺任意尺寸或外观变化均可识别。

## 6. ROI 与坐标契约

- 原始解码图像左上角为原点，x 向右、y 向下，单位为像素。
- ROI 为四个整数；x、y 非负，宽高为正，整个区域必须位于原图内。越界直接报错，不自动裁剪。
- 模板必须完整落在 ROI 内，首版不支持只露出一部分的目标。
- 在 ROI 中匹配后，返回矩形必须加回 ROI 偏移，始终使用原图的全局坐标。
- `rect` 包含整数 `x`、`y`、`width`、`height`，矩形覆盖半开区间 `[x, x + width)` 和 `[y, y + height)`。
- `center` 使用浮点像素坐标，分别为 `x + width / 2`、`y + height / 2`；执行点击前由调用者转换为整数。
- Python 内存入口不猜测设备坐标，窗口坐标字段为空。
- Appium 扫描同时记录截图尺寸和窗口尺寸。默认 `coordinate_mode=screenshot` 返回 `coordinate_mapping=unverified`，窗口矩形和窗口中心为空，仍保留有效的截图坐标。
- `coordinate_mode=full_window` 表示调用者确认截图与窗口同方向、同原点、覆盖范围一致。尺寸相等采用恒等映射；尺寸不同时，令 `sx=window_width/image_width`、`sy=window_height/image_height`，要求 `abs(sx/sy - 1) <= 0.005`，再分别缩放 x/width 与 y/height，记录比例与转换结果。窗口矩形允许浮点数，不能提前取整累积误差。
- 仅凭两者宽高比相近不能证明坐标可映射。无法确认覆盖范围、存在裁边/黑边或不明偏移时，不应启用 `full_window`；已启用但比例检查失败时报 `COORDINATE_MAPPING_ERROR`，不能输出猜测坐标。方向或窗口在采集期间改变仍按 `SCREEN_CHANGED` 处理。
- 首版不自动校正状态栏、导航栏或设备厂商引入的偏移，不混用截图坐标和窗口坐标。

## 7. 元素对象与内部结果

### 7.1 公开返回的 ImageElement

元素至少提供以下只读属性，Python 与 Robot 访问同一对象：

| 属性 | 语义 |
| --- | --- |
| `rect` | 截图全局坐标中的 `x`、`y`、`width`、`height` |
| `location` | 从矩形派生的 `x`、`y` |
| `size` | 从矩形派生的 `width`、`height` |
| `center` | 从矩形派生的中心点 `x`、`y` |
| `score`、`scale` | 通过校验的匹配分数与模板缩放比例 |
| `image_size`、`template_size` | 截图与原始模板尺寸 |
| `scan_id` | 关联本次扫描日志和可选诊断的标识 |
| `coordinate_mapping`、`window_size` | 坐标换算状态与已知窗口尺寸 |
| `window_rect`、`window_center`、`window_scale` | 显式请求且通过检查后得到的窗口坐标与换算比例 |
| `debug_paths`、`diagnostic_error` | 显式导出诊断时的文件路径与写入错误信息 |

`rect`、`location`、`size`、`center` 使用固定键名的字典；返回副本，外部修改不得改变元素内部记录。对象提供 `to_dict()` 输出可转换为 JSON 的元数据。

元素不保存 Appium 会话、原始截图字节或图像数组，不包含服务端 element id，也不假装支持 WebElement 的动态属性查询。对象表示采集时的画面，页面变化后需重新查找。首版不提供 `click()`。

### 7.2 内部匹配结果及诊断

内部仍用结构化结果描述所有扫描状态，供构造元素、生成异常和诊断使用，至少包含：

| 字段 | 语义 |
| --- | --- |
| `scan_id` | 本次扫描唯一标识，用于关联日志和诊断目录 |
| `status` | `matched`、`not_found` 或 `ambiguous` |
| `rect`、`center` | 仅 `matched` 时提供可直接采用的截图坐标，否则为空 |
| `score` | 最佳有效候选的分数；没有有限分数时为空 |
| `scale` | 最佳候选的请求缩放比例；实际匹配尺寸以候选矩形为准 |
| `best_candidate` | 最佳候选的矩形、分数和比例，未通过阈值时也保留用于分析；无候选时为空 |
| `second_candidate` | 另一个位置上达到阈值的最高分候选，用于解释歧义；不存在这样的候选时为空 |
| `image_size`、`template_size` | 原图及原始模板尺寸 |
| `roi` | 本次实际使用的原图坐标搜索区域 |
| `parameters` | 实际使用的阈值、缩放范围、步长、分差及算法等配置 |
| `coordinate_mapping` | `not_applicable`、`unverified`、`identity` 或 `scaled` |
| `window_size` | Appium 窗口尺寸，即使未启用坐标换算也记录；Python 内存入口为空 |
| `window_rect`、`window_center`、`window_scale` | 经确认的窗口坐标及 x/y 换算比例；无法映射或无设备时为空 |
| `elapsed_ms` | 从读取输入/设备截图开始到匹配结束的耗时，不含写诊断文件的时间 |
| `debug_paths` | 已生成的诊断文件路径，未生成时为空 |
| `diagnostic_error` | 写诊断失败时的说明，正常时为空 |

元数据不得包含 ndarray、图片 Base64、原始图片字节或 WebElement，避免 Robot 日志膨胀；除明确为空的字段外，数据类型必须固定，并可转换为 JSON。图片缓冲区只在本次调用内部使用，匹配与可选导出完成后释放引用，不随元素长期保留。

`not_found` 和 `ambiguous` 不能伪装成 `matched`。对应异常携带可序列化的候选摘要、参数及诊断路径，便于调用者区分未找到和歧义。读取失败、参数错误及设备连接失败保留各自异常，不能降级成未找到。

## 8. Appium 适配边界

- 使用已打开的 AppiumLibrary 会话，不自行创建或关闭会话，不启动服务器，不修改插件或匹配设置。
- 获取当前上下文，必要时切换到 `NATIVE_APP`，在 finally 路径恢复原上下文；成功或失败都必须尝试恢复。恢复失败需显式报告，不能静默留在错误上下文。
- 使用 `get_screenshot_as_png()` 读取一帧，在内存中解码、匹配并构造元素。关闭诊断时，本库不写入截图、临时文件或中间图片；匹配失败也不自动落盘。
- 截图前后读取窗口尺寸与方向；发生变化则报告 `SCREEN_CHANGED`，由调用者决定重试。尺寸和方向检查不代表画面内容完全静止。
- 若不得不使用 AppiumLibrary 的内部会话方法，必须封装在单独的适配层，并对已验证的库版本和升级风险作说明；匹配核心不得调用该内部方法。
- 不返回具有持续有效语义的元素对象。扫描结果只描述采集时的画面，画面变化后需要重新扫描。

## 9. 诊断材料

默认 `debug=none`，正常查找和异常路径均不生成图片文件。调用者显式指定 `always` 时保存每次结果，指定 `on_failure` 时保存未找到、歧义及已取得输入的执行错误。

诊断导出是扫描后的可选副作用，不参与截图传递或匹配。任何诊断文件都不得被重新读入以完成当前扫描；默认配置下诊断输出目录可以不存在，运行也不依赖该目录可写。

每个独立诊断目录至少包含：

1. `source`：本次实际参与扫描的原始输入字节或原始 Appium PNG，不绘框、不重压缩、不重新截图；扩展名与实际编码一致。
2. `template`：本次读取的模板原始字节，扩展名与实际编码一致。
3. `annotated.png`：原图坐标中的 ROI、最佳候选、第二候选、状态、分数与比例。未通过阈值的候选必须明确标记，不画成已通过结果。
4. `metadata.json`：结果、实际参数、有效及跳过的比例、尺寸、耗时、依赖版本和异常说明。

目录命名必须含唯一扫描标识，不覆盖历史记录。默认写入 Robot 本次输出目录，不写入模板目录，不自动加入 Git。内容处理和保存均在本机完成。

读取输入之前失败时不生成伪造图片。诊断写入失败需保留原扫描结果或原异常，并提供诊断错误信息；不能用保存图片的异常替换匹配错误。

## 10. 错误与依赖

至少区分以下错误标识：`IMAGE_NOT_FOUND`、`AMBIGUOUS_IMAGE_MATCH`、`INVALID_ARGUMENT`、`IMAGE_READ_ERROR`、`UNSUPPORTED_TEMPLATE`、`DEGENERATE_TEMPLATE`、`NO_VALID_SCALE`、`APPIUM_SESSION_ERROR`、`SCREEN_CHANGED`、`CONTEXT_RESTORE_ERROR`、`COORDINATE_MAPPING_ERROR`。异常需保留原始原因；已有扫描异常时，上下文恢复失败作为附属错误报告，不覆盖主错误。

依赖以最小集合为原则：OpenCV、NumPy；Robot Framework 和 AppiumLibrary 位于适配层。优先使用 `opencv-python-headless`，不依赖图形窗口，也不同时安装 headless 与 GUI 两种 OpenCV 发行包。

Python 最低版本拟与现有 bridge 保持一致为 3.9，但必须以可安装的依赖版本和实际测试为准；实施时记录已验证版本组合，不在尚未验证时承诺兼容所有 Python/OpenCV/AppiumLibrary 版本。

不设置图像匹配的全局可变参数；每次调用使用独立配置。仅公开明确登记的 Robot 关键字，库作用域采用 SUITE。首版不做跨扫描图像缓存或后台线程。

## 11. 验收条件

1. 指定模板即可通过现有会话返回 `ImageElement`，无需传截图路径或 driver；同尺寸、已知位置的目标返回正确矩形。在人工构造且比例落在扫描网格的样例中，左上角误差不超过 2 像素。
2. 模板分别以 0.50、0.75、1.00、1.25、1.50、2.00 倍放入截图，返回正确位置和对应实际尺寸；至少一个样例包含相似干扰图案。
3. 加入不落在默认步长上的缩放样例，验证细化步长能改善结果；不能把离散多尺度搜索宣称为任意连续比例保证。
4. ROI 不从原点开始时，坐标正确加回偏移；ROI 外的相似目标不能影响选择。
5. 不存在目标时抛出 `IMAGE_NOT_FOUND`；两个不同位置的近似等分目标抛出 `AMBIGUOUS_IMAGE_MATCH`；多个比例命中同一目标时不误报歧义。
6. 覆盖中文路径、非法图片、透明模板、纯色模板、非法阈值、无效比例和越界 ROI。
7. 默认配置下验证无截图文件读取、截图写入或临时文件操作；原图与模板均传内存字节时，核心不执行任何文件系统读写。显式导出时验证诊断原图与本次输入字节一致、标注坐标与结果一致，且保存不触发第二次截图；诊断写入失败不覆盖原错误。
8. 使用会话替身验证 Appium 上下文恢复、设备错误传播和方向/尺寸变化；真实设备验收单独记录，不把替身测试当作实机通过。
9. Python 内存入口在无网络、无 Appium 服务时可运行；不触发点击或修改模板文件。验证元素属性一致、外部修改字典不改变内部坐标，元数据与日志中不包含图片缓冲区。

测试以匹配正确性、误匹配、坐标和故障边界为重点，不为简单转发接口单独堆叠镜像实现的测试。性能记录原图尺寸、ROI、比例数及耗时，不预先承诺固定毫秒数；通过以上检查后再评估是否需要缓存或粗细两级搜索。

## 12. 实现组织

1. 实现独立匹配核心与内存图片入口，完成多尺度、ROI 和歧义验收。
2. 实现 `ImageElement`、异常契约与 Robot 主入口，完成返回对象验收。
3. 接入现有 Appium 会话的内存截图和可选诊断导出，完成无中间文件、设备与坐标验证。
4. 用真实按钮模板校准阈值及比例范围，提供最小调用说明。

实施顺序不扩大首版范围。自动点击、复杂透明模板处理及更强的视觉算法需要另行确定需求。
